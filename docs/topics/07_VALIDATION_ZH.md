# 07 验证与能力边界：怎样判断“跑通、学会、有效”

[主要概览](../LEARNING_OVERVIEW_ZH.md) · [上一篇：检测与监督](06_DETECTION_TRAINING_ZH.md)

前六篇说明网络为何这样计算，本篇说明什么证据可以支持什么结论。当前状态的统一摘要在概览，原始运行记录继续由 [STATUS](../../code_walkthrough/STATUS.md)、[trace](../../code_walkthrough/figures/r4det_trace.json) 和[运行手册](../R4DET_RUNBOOK.md)维护。

## 1. 四个层次为什么不能跳过

| 层次 | 验证对象 | 通过条件 | 仍不能证明 |
|---|---|---|---|
| L0 环境 | 依赖、CUDA 算子、前向接口 | 指定样本可运行 | 权重完整或检测正确 |
| L1 权重与单帧 | 模型参数匹配和路径执行 | 严格加载、有效输出与阶段记录 | 训练能优化、真实融合收益 |
| L2 训练 | loss、梯度与更新 | 小数据可过拟合、保存恢复正常 | 独立数据泛化 |
| L3 正式指标 | 真实同步数据和固定 split | 完整评测及对照 | 任意环境下可部署 |

现有记录支持 TJ4D 的 L1。文档中没有足够证据把 L2/L3 标成完成。主链中有条件分支，所以总状态 PASS 也不等于每一个模块都执行。

## 2. 先确认测量和几何，再比较模型

雷达—相机融合依赖时间、空间和字段合同。应核对点的单位/速度符号、图像通道和归一化、内外参、图像与 BEV 增强矩阵、序列边界及前帧有效性。错误的合同可能照样生成有限值和正确 shape。

一个最小几何检查是：选已知三维点，投影到原图；再施加训练/测试增强，用更新矩阵投影，确认它落在增强后同一位置；最后计算对应 BEV cell。这个闭环比单看网络输出是否有框更能定位坐标问题。

## 3. 消融必须说明改变了什么

| 检查 | 操作 | 可以得到的结论 |
|---|---|---|
| 形状检查 | 合成/复制输入，观察接口与维度 | 结构可以接通 |
| 固定权重干预 | 固定输入，旁路一个模块 | 当前模型对模块的敏感性 |
| 条件路径 | 真实有效历史/无效历史，有/无实例 | 分支是否执行、旁路是否符合约定 |
| 正式消融 | 相同 split 与协议，匹配各配置训练 | 模块对检测指标的贡献 |

当前配置存在 painting 视觉路径，所以只关掉最终跨模态融合不等于 RadarOnly。黑图也不等于独立训练的 RadarOnly 基线。相机失效时是否受控降级，是需要实现并验证的工程能力。

## 4. AP、Recall 与弱目标问题

Recall 衡量真目标被找回的比例；Precision 衡量输出中多少正确；AP 汇总不同分数阈值下的精确率—召回关系，并依赖匹配阈值、类别和 ignore 规则。不同 split 或不同 IoU 规则下的 AP 不能直接比较。

若关心远距少点目标，应按距离、每目标点数和类别切片，结合 FP/frame、定位误差与漏检统计。总体 AP 的改善可能主要来自近距目标，不能直接说明强目标附近弱目标的召回提高。

点云输入已经损失部分阈值前信息。判断物理旁瓣、多径或真实弱回波是否恢复，还需要原始谱/ADC、候选来源和相应标签，不能从 IGDR 后的 BEV 图直接推出。

## 5. 本地已有证据的使用规则

公开 smoke 的相机图是由雷达投影生成的代理图，真实雷达、标定和标签并不能补足真实相机观测。该样本适合学习软件路径；正式融合评测需原始同步相机和完整官方 split。

阶段 trace 的耗时与运行手册的 FP32/FP16 耗时来自不同执行记录、计时范围和配置，不应拼成严谨性能排行。部署计时需固定输入、预热、同步方式、设备和统计次数。

标签依赖审计应固定输入和权重，逐项删除或扰动 GT 字段并比较预测；若接口直接报错，先区分数据包装依赖和预测计算依赖，再修正接口。这是待做的检查方法，本次没有执行该审计。

## 6. 完成这一轮学习的标准

能够解释输入信息损失、两种网格尺度、深度分布、两种投影方向、时序有效性、实例调制和 anchor 解码；能从概览指出每项证据是配置事实、代码事实还是历史运行事实。随后按[运行手册](../R4DET_RUNBOOK.md)复跑，再依[点云融合实验路线](../POINT_CLOUD_FUSION_LEARNING_ZH.md)推进真实数据、训练与对照实验。
